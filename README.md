# BackendLearningLab: OrderFlow System
### The Anti-Vibe-Coding Professional Java Backend Engineering Laboratory

> **"If you cannot explain why a line of code exists, you do not own that code — the code owns you. This repository is built to teach you how enterprise Java systems work internally without relying on AI magic or superficial vibe-coding."**

---

## 1. Project Purpose

**BackendLearningLab** is an engineering-first learning platform built around a realistic backend application called:
**"OrderFlow — E-Commerce Order Processing & Inventory System"**.

Unlike tutorial projects that simply dump autogenerated code, this lab teaches:
- **WHY** each technology is used and what real problem it solves.
- **HOW** each technology works mechanically under the hood (memory, threads, network, disk).
- **HOW** to implement it manually from first principles before using abstractions.
- **HOW** to recognize and diagnose catastrophic beginner mistakes (N+1 queries, SQL injection, connection leaks, poison pills, deadlocks, stale caches).
- **HOW** to refactor fragile prototype code into production-hardened systems.

| **Phase 1** | **Core Java & Concurrency** | Writing memory-efficient, thread-safe, non-blocking code without memory leaks. |
| **Phase 1** | **Maven & PostgreSQL** | Managing reproducible dependency lifecycles and designing normalized 3NF relational schemas with B-Tree indexes. |

| **Phase 3** | **Redis Caching** | Sub-millisecond in-memory lookups, Cache-Aside pattern (`@Cacheable`, `@CachePut`, `@CacheEvict`), distributed rate limiting, and JWT logout revocation. |
| **Phase 4** | **Apache Kafka & EDA** | Asynchronous event-driven decoupling, consumer groups, Dead Letter Topics (DLT), poison pill defense, and solving the Dual-Write problem via the Transactional Outbox Pattern. |

## 3. The 10-Step Anti-Vibe-Coding Learning Protocol

For every technology in this project, execute this deliberate practice cycle:

```
[ 1. Learn Concept ] ──────► [ 2. Run Smallest Demo ] ──────► [ 3. Read Internals ]
                                                                     │
[ 6. Fix With Pattern ] ◄─── [ 5. Debug Root Cause ] ◄─── [ 4. Break Intentionally ]
       │
       ▼
[ 7. Rewrite From Memory ] ──► [ 8. Implement Feature ] ──► [ 9. Explain Verbally ]
                                                                     │
                                                                     ▼
                                                   [ 10. Build Variation Without AI ]
```

1. **Learn concept:** Read the dedicated architectural deep-dive in `docs/`.
2. **Run smallest example:** Run the standalone runnable demo in `examples/`.
3. **Read implementation:** Inspect the bytecode and framework source code (`F12` / `Ctrl+Click` into Spring/Hibernate classes).
4. **Break implementation intentionally:** Inject bad inputs, disable network sockets, pass nulls, or trigger concurrent race conditions.
5. **Debug:** Inspect thread dumps, PostgreSQL `EXPLAIN ANALYZE`, and SLF4J log traces.
6. **Fix:** Apply the production-grade architectural pattern.
7. **Rewrite without looking:** Delete the file and reconstruct it from memory.
8. **Implement project feature:** Integrate the concept into the main OrderFlow application.
9. **Explain it verbally:** Articulate the trade-offs out loud as if in a technical interview.
10. **Build a small variation without AI:** Implement an alternate scenario without opening an AI prompt.

## 5. How to Run and Verify the Entire System

### 1. Execute All 21 Automated Integration Tests
```bash
mvn test
```
*Executes all 6 comprehensive test suites covering Pure JDBC, Spring Data JPA, MockMvc REST API, Spring Security 6, Stateless JWT, Redis Caching, Rate Limiting, the Transactional Outbox, Consumer Idempotency, and Health Probes with 100% success.*

### 2. Run the Standalone Interactive Demos
```bash
# 1. Plaintext vs Fast SHA-256 vs BCrypt Password Storage
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.examples.security.PlaintextVsBCryptDemo"

# 2. Pure Java Manual HMAC-SHA256 JWT Construction & Tamper Detection
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.examples.security.ManualJwtDemo"

# 3. Standalone In-Memory Redis Key-Value & LRU Eviction Simulation
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.examples.redis.StandaloneRedisDemo"

# 4. Standalone Pure Java Apache Kafka Commit Log & Rebalance Simulation
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.examples.kafka.StandaloneKafkaDemo"

# 5. Clean Code & SOLID Refactoring Demonstration
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.examples.cleancode.SolidAndRefactoringDemo"

# 6. Core Java & Concurrency Demos
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.concurrency.CompletableFutureAsyncDemo"
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.concurrency.DeadlockAndPreventionDemo"

# 7. Hibernate Internals: Dirty Checking & N+1 Problem Demos
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.spring.hibernate.demo.EntityLifecycleAndDirtyCheckingDemo"
mvn exec:java "-Dexec.mainClass=com.backendlearninglab.spring.hibernate.demo.NPlusOneProblemDemo"
```

### 3. Spin Up the Local Infrastructure Stack (Docker)
```bash
# Starts PostgreSQL (5432), Redis (6379), Apache Kafka KRaft (9092), and Kafka UI (8081)
docker compose up -d

# Start the Spring Boot backend
mvn spring-boot:run
```

## 6. Complete REST API Endpoint Catalog

| HTTP Method | Endpoint | Access Level | Description |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/health` | Public | System Health Probe (Database connection, JVM heap memory, uptime) |
| `POST` | `/api/v1/auth/register` | Public | Register new customer account with BCrypt password hashing |
| `POST` | `/api/v1/auth/login` | Public | Authenticate credentials and receive cryptographically signed JWT |
| `GET` | `/api/v1/auth/me` | Authenticated | Retrieve current authenticated user profile from token |
| `GET` | `/api/v1/products` | Public | List active merchandise (Cached in Redis via `@Cacheable`) |
| `GET` | `/api/v1/products/{id}` | Public | Lookup product by ID (Cached in Redis via `@Cacheable`) |
| `POST` | `/api/v1/products` | `ADMIN`, `INVENTORY_MANAGER` | Create merchandise with initial warehouse inventory stock |
| `PUT` | `/api/v1/products/{id}/price` | `ADMIN`, `INVENTORY_MANAGER` | Update price (Synchronously refreshes cache via `@CachePut`) |
| `DELETE` | `/api/v1/products/{id}` | `ADMIN` | Deactivate product (Evicts cache via `@CacheEvict`) |
| `GET` | `/api/v1/users` | `ADMIN` | List all users (Forbidden for regular `USER` returning HTTP 403) |
| `POST` | `/api/v1/orders` | Authenticated | Atomic checkout with inventory deduction, rollback safety, and Transactional Outbox event generation |
